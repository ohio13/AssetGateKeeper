# AssetGatekeeper Enterprise

Everything here is additive. A single-machine studio runs v1 exactly as before:
no config file, no extra packages, SQLite, local sign-in. Enterprise behaviour
turns on only when a deployment asks for it, and it **fails closed** when it
cannot do what was asked.

```
enterprise/
  config.py     typed config; secrets only from the environment
  store.py      SQLite today, pooled PostgreSQL when a DSN is set
  analytics.py  compliance, polygon growth and error trends
  rbac.py       path-based grants, deny-wins
  auth.py       OIDC (PKCE), SAML 2.0 SP, signed sessions
  vcs.py        Git LFS pointers and Perforce Helix Core
  remote.py     validate depot paths / URLs, plus the runner farm
  cli.py        the `agk-enterprise` command

plugins/
  preflight_core.py        the DCC-agnostic check
  blender/preflight_panel.py
  maya/maya_preflight.py
  max/max_preflight.py
  unreal/unreal_preflight.py
```

Optional dependencies are grouped by feature, so a studio installs only what it
runs:

| Extra | Brings | For |
|---|---|---|
| `.[postgres]` | `psycopg[binary]`, `psycopg-pool` | the central database |
| `.[enterprise]` | `psycopg`, `cryptography` | PostgreSQL + RS256/ES256 tokens |
| `.[saml]` | `signxml` | SAML assertion signatures |

Without them the corresponding feature refuses with an install hint - it never
falls back to something weaker.

## 1. PostgreSQL backend and historical telemetry

### Why

One SQLite file per workstation is not a metric, it is a rumour. A studio points
every client at one server instead:

```toml
[enterprise.database]
dsn = "postgresql://agk@db.studio.internal:5432/assets"
pool_min = 4
pool_max = 40
```

`AGK_DATABASE_DSN` overrides the file, which is how a container deployment is
configured without a config volume.

### How the SQLite code keeps working

The rest of the codebase still writes `?` placeholders and `INSERT OR REPLACE`.
`enterprise.store.SqlTranslator` rewrites exactly what PostgreSQL spells
differently:

| SQLite | PostgreSQL |
|---|---|
| `?` | `%s` |
| `INSERT OR REPLACE` | `INSERT ... ON CONFLICT (key) DO UPDATE SET ...` |
| `INTEGER PRIMARY KEY AUTOINCREMENT` | `GENERATED BY DEFAULT AS IDENTITY` |
| `COLLATE NOCASE` | dropped |
| `GROUP_CONCAT(x, char(10))` | `string_agg(x, chr(10))` |
| `PRAGMA ...` | no-op |
| inline `REFERENCES` | moved to `ALTER TABLE ... ADD CONSTRAINT` (second pass) |

Two deliberate refusals:

* an upsert into a table whose conflict key is not declared in
  `store.PRIMARY_KEYS` raises `StoreError` instead of writing with the wrong
  semantics;
* anything else it does not understand raises with the statement attached. A
  silently mistranslated query returns a confident wrong number, which is worse
  than a crash.

Foreign keys are moved to a second pass because the AssetHealth schema declares
`verdicts.project_id REFERENCES projects(id)` before `projects` exists - legal in
SQLite, rejected by PostgreSQL.

### Migrating an existing dashboard

```bash
python -m pip install "asset-gatekeeper[postgres]"
agk-enterprise migrate --sqlite asset_health.db \
    --dsn postgresql://agk@db:5432/assets --init-schema
```

### The dashboard runs on the same abstraction

AssetHealth no longer opens SQLite itself. Every query goes through
`enterprise.store.Store`, so the backend is a deployment decision:

```bash
asset-health --db postgresql://agk@db:5432/assets   # one server, every client
asset-health --db metrics.db                        # unchanged, SQLite
export AGK_DB_URL=postgresql://agk@db:5432/assets   # or this
```

* one `Store` per target, memoised: a pool per request would be a connection
  storm;
* SQLite still gets a fresh connection per unit of work, which is what keeps WAL
  readers concurrent without sharing a handle across threads;
* `INSERT ... RETURNING id` on PostgreSQL, `lastrowid` on SQLite, behind one
  `insert_id()` helper so the row-creating handlers cannot drift;
* rows come back as a wrapper that supports both `row["column"]` and `row[0]`,
  because the dashboard was written against `sqlite3.Row` and a handful of
  positional reads would otherwise fail only in production;
* `sqlite3.Error` handlers now catch `(sqlite3.Error, StoreError)`, so a
  PostgreSQL failure reports its reason instead of a bare 500.

`init_db` creates the schema once per engine: the shipped SQLite script is
translated (identity columns, dropped `COLLATE NOCASE`, foreign keys moved to a
second pass, `--` comments stripped) and column probes use `information_schema`
instead of `PRAGMA`.

### The `/analytics` page

```
GET /analytics?since=90d&bucket=week[&project_id=N]   HTML
GET /api/analytics?since=90d&bucket=week              the same numbers as JSON
```

The page renders the three trends the CLI reports: compliance per bucket (with
healed assets counted once, and shown separately), polygon growth as average and
peak with the ratio between them, and error clusters grouped by signature with
first/last sighting. `since` accepts `7d`, `30d`, `90d`, `12m`, `3y`; `bucket`
accepts `day`, `week`, `month`. Unknown values fall back to the defaults rather
than erroring - a bookmark with a stale parameter should not show a stack trace.

Empty sections explain themselves: a growth chart with no data says the verdicts
carried no triangle metric, because an empty panel and "your assets are all
zero triangles" look identical otherwise.

The source is opened **read-only**, rows are copied in foreign-key order, and
inserts are `ON CONFLICT DO NOTHING`, so re-running after a partial failure
resumes instead of duplicating. Nothing is deleted from the SQLite file.

### Trends

```bash
agk-enterprise trends compliance --db metrics.db --since 18m --bucket month
agk-enterprise trends growth     --db metrics.db --since 2y --bucket quarter
agk-enterprise trends errors     --db metrics.db --since 90d --limit 15
```

* **compliance** - passing share per bucket. A healed asset counts as passing
  (it did pass) but is reported separately, so healing cannot inflate the number.
* **polygon growth** - average and peak triangles per bucket, read from the
  verdict metric text. A rising average with a flat asset count is a content
  problem; a flat average with a rising count is a scope problem.
* **errors** - problems folded into signatures (`72,500 triangles exceeds the
  50,000 budget` and the same line for another asset are one cluster), ranked by
  count, with first and last sighting.

Windows are `90d`, `18m`, `2y` or `2024-01-01`. Buckets are sortable strings
(`2026-10-31`, `2026-10`, `2026-W44`), so a chart never needs to reason about
timezones. Every query accepts `--project`.

## 2. Enterprise authentication and path-based RBAC

### Identity

```toml
[enterprise.oidc]
issuer = "https://studio.okta.com"
client_id = "0oa1..."
redirect_uri = "https://agk.studio.internal/enterprise/callback"
allowed_domains = ["studio.example"]      # only these emails may sign in
groups_claim = "groups"

[enterprise.saml]
entity_id = "https://agk.studio.internal/saml"
sso_url = "https://adfs.studio.internal/adfs/ls/"
x509_cert = "-----BEGIN CERTIFICATE-----..."
allow_unsigned = false                    # keep false; it exists for a lab IdP
```

Secrets are **environment only** - `AGK_OIDC_CLIENT_SECRET`,
`AGK_SAML_CERT`, `AGK_SESSION_SECRET`. A `client_secret` in the config file is
refused at load time with an explanation, because a committed secret is a leaked
secret.

What the implementation enforces:

* `alg: none` is rejected before any signature work;
* the key decides the algorithm - an RSA key never validates an HS256 token
  (algorithm-confusion);
* `exp`, `nbf`, `iat`, `iss`, `aud` and `nonce` are all required;
* PKCE S256 on the authorization request;
* SAML assertions must be signed; missing `signxml` is a refusal with the install
  command, and `allow_unsigned` has to be set on purpose;
* sessions are HMAC-SHA256 cookies whose expiry is inside the signed payload.

### Authorization

```toml
[enterprise.rbac]
default_deny = true

[[enterprise.rbac.grant]]
subject = "group:environment-leads"
path = "/environments/**"
permissions = ["rules.override", "rules.edit", "assets.validate"]

[[enterprise.rbac.grant]]
subject = "group:contractors"
path = "/characters/**"
permissions = ["rules.override"]
deny = true
```

* Paths: `/environments/**` (subtree), `/characters/*` (one level),
  `/environments/rock` (that folder). Comparison is case-insensitive and
  normalises backslashes, because Windows and Perforce both are.
* `..` in a policy path is an error, not something to resolve helpfully.
* **Specificity wins, deny beats allow** at equal specificity. Moving a rule up
  or down the file changes nothing - which is what stops a policy file from being
  theatre.
* Permissions: `rules.read`, `rules.override`, `rules.edit`, `assets.validate`,
  `assets.heal`, `workstation.review`, `audit.read`, `admin.users`, `admin`.

Inspect a decision before trusting it:

```bash
agk-enterprise rbac-check --path /environments/rock/crag.obj \
    --group environment-leads --permission rules.override
```

```
user    ana (group:environment-leads, user:ana)
path    /environments/rock/crag.obj
may     assets.validate, rules.edit, rules.override
ALLOW   rules.override: granted by group:environment-leads for /environments/**
```

`rbac-check` also prints policy warnings (global admin, `default_deny = false`),
which is the list a security review will ask for.

## 3. Perforce Helix Core and Git LFS

### Git LFS

A pointer file is detected by content, not by suffix. The gate resolves it
through `git lfs smudge` and refuses to validate the 130-byte text as if it were
art - if Git LFS is not installed, that is an error naming the real size:

```
normal_Albedo.png is a Git LFS pointer and 'git' is not on PATH, so its real
(41,943,040 byte) content cannot be read
```

### Perforce, without a workspace

```bash
# what a runner does, from anywhere on the farm
agk-enterprise validate //depot/proj/main/env/rock.obj@head
agk-enterprise validate 123456            # a changelist
```

The client uses four read-only commands - `p4 info`, `p4 describe`, `p4 files`,
`p4 print` - always argv-only (never a shell string), always with a timeout. The
existing `vcs_hooks/p4_pre_submit.py` trigger validates the *depot* content of
each file in a changelist before the submit is committed, so an artist's shelf is
reviewed as it will land, not as it looks in their workspace.

### Runner farm

```bash
agk-enterprise hub --port 9000 --token $AGK_RUNNER_TOKEN --submit //depot/proj/main/env/...
agk-enterprise runner --hub http://hub:9000 --token $AGK_RUNNER_TOKEN --jobs 4
```

Three endpoints, no framework:

```
POST /claim   {"runner": "name"}        -> 200 job JSON | 204 no work
POST /result  {"id": "...", "report": {}} -> 202
GET  /status                            -> queue depth
```

Runners are machines, so auth is one bearer token - not a session cookie that
would end up pasted into a CI variable. Every fetch is size-capped and timed out;
a runner reports an error instead of crashing on one bad asset.

## 4. In-DCC pre-flight

Every adapter reads the numbers from the DCC that owns them and asks
`plugins/preflight_core.py` for the verdict - no export, no temp file, and the
panel cannot disagree with the gate because both use the same budget objects.

| DCC | Entry point | What it measures |
|---|---|---|
| Blender 3.6+ | N-panel **Asset Gatekeeper** (`preflight_panel.py`) | evaluated depsgraph polygons, material slots, image sizes, zero-area faces |
| Maya 2022+ | `maya_preflight.show()` or shelf button | `polyEvaluate` faces/tris, shading-engine materials, `file` node sizes |
| 3ds Max 2021+ | `max_preflight.show()` (Python in MAXScript) | `getPolygonCount`, multimaterial slots, bitmap sizes |
| Unreal 5.x | `unreal_preflight.run_and_log()` / `show()` | StaticMesh LOD0 triangles and vertices, material slots |

Each report contains the same four things: the numbers, the budget they were
compared against, the errors/warnings, and - the one artists actually act on - a
**fuzzy tag suggestion**:

```
BLOCKED - 3 error(s)
triangles 4,000   vertices 2,800
materials 4
budget    tris<=1,500  materials<=1  texture<=64px
SUGGESTED character  (rename the folder)
[x] 4,000 triangles exceeds the 1,500 budget (+2,500); decimate or move it to a tag with a bigger budget
[x] 4 material slots exceeds the 1 slot budget (each slot is a draw call); merge or atlas
[x] texture 'boss_Albedo.png' is 256x256, over the 64px budget
```

In strict tag mode a misspelled department folder is an error in the panel, so it
is caught before export rather than rejected at submit.

## 5. Schema migrations, SIEM forwarding and read replicas

### Versioned migrations

```
migrations/0001_baseline.up.sql / .down.sql
migrations/0002_verdict_metrics.up.sql / .down.sql
```

```bash
agk-enterprise migrate --dsn $AGK_DB_URL --verify     # history + zero-downtime rules
agk-enterprise migrate --dsn $AGK_DB_URL --plan       # what would run, changes nothing
agk-enterprise migrate --dsn $AGK_DB_URL --apply
agk-enterprise migrate --dsn $AGK_DB_URL --down --to 0
```

* Every applied version is recorded with its **checksum**; editing an applied
  migration is reported instead of silently re-run.
* `SET lock_timeout` (2 s default) precedes every migration: if the lock cannot
  be taken, the migration fails fast rather than queueing every writer behind it.
* The linter refuses DDL that takes an exclusive lock (DROP COLUMN, type changes,
  renames, SET NOT NULL, TRUNCATE) and the runner rewrites what it can do safely:
  `CREATE INDEX` becomes `CREATE INDEX CONCURRENTLY` (making that migration
  non-transactional automatically), and `ADD CONSTRAINT ... FOREIGN KEY` gains
  `NOT VALID`.
* `--verify` after a rollout also checks that the tables the code needs exist.

### SIEM forwarding

```toml
[enterprise.audit]
enabled = true
file = "/var/log/agk/audit.jsonl"
syslog_host = "siem.studio.internal"   # RFC 5424, UDP or TCP
syslog_port = 514
webhook_url = "https://splunk.studio.internal:8088/services/collector"
webhook_batch = 50
min_severity = "notice"
```

Token for the webhook: `AGK_AUDIT_WEBHOOK_TOKEN` (never in the file).

A `webhook_url` containing `/services/collector` is treated as Splunk's HTTP
Event Collector: each event is sent in HEC's own envelope (`time`, `host`,
`source`, `sourcetype` `_json`, `event`) with `Authorization: Splunk <token>`.
Any other URL receives `{"schema": "agk.audit/1.0", "events": [...]}`. Syslog
lines carry the sending machine's name as the RFC 5424 HOSTNAME, the process id
as PROCID and the event name (`budget.violation`, ...) as MSGID.

Events: `auth.token.rejected`, `auth.login.failed`, `rbac.denied`,
`rbac.override`, `budget.violation`, `admin.action`, `migration.applied` - each a
JSON object with `schema`, `ts`, `event`, `severity`, `actor`, `action`, `path`,
`outcome`, `project_id`, `request_id`, `remote`, `detail`. Credentials are
redacted recursively before serialisation, and the request path never blocks: a
bounded queue drops and counts when a collector is slow.

### Read replicas and circuit breakers

```toml
[enterprise.database]
dsn = "postgresql://agk@primary:5432/assets"
read_dsns = ["postgresql://agk@replica-1:5432/assets"]
breaker_threshold = 5
breaker_reset_seconds = 30
health_interval_seconds = 30
```

`/analytics`, `/api/analytics` and audit listings read through `Store.reader()`,
which round-robins healthy replicas and falls back to the primary. Each endpoint
has its own breaker: after `breaker_threshold` consecutive failures it opens,
refuses calls immediately (no 30-second timeout per request), and half-opens a
single probe after `breaker_reset_seconds`. The health loop shares the same
breaker, so there is one truth per endpoint.

## Security posture

| Concern | Behaviour |
|---|---|
| Secrets in a repo | refused at config load; environment only |
| Token in a browser | never: the bridge is server-to-server, sessions are HttpOnly cookies |
| Unsigned SAML | refused unless `allow_unsigned` is explicitly set |
| Algorithm confusion | key selects the algorithm, never the token |
| Path traversal in policy | `..` is an error |
| Shell injection in VCS calls | argv only, no shell, timeouts |
| Runner auth | bearer token, no browser session |
| Silent SQL mistranslation | refused with the statement attached |

## What is verified, and what needs your infrastructure

**Verified in this repository** (`tests/test_enterprise.py`, 148 assertions, no
network and no external services):

* config parsing, secret refusal, env overrides, RBAC grant loading;
* path matching, specificity, deny-wins, director handling, traversal refusal;
* JWT verification (HS256 good/expired/tampered/issuer/audience/nonce/alg=none),
  RS256 failing closed without `cryptography`, OIDC discovery + PKCE URL +
  issuer mismatch, JWK-to-PEM conversion, session issue/verify/expiry/forgery;
* unsigned SAML refused, signed-without-`signxml` refused, lab opt-out parses;
* SQL translation (placeholders, upserts, unknown table refusal, `GROUP_CONCAT`),
  schema two-pass foreign keys, SQLite store round-trip through the real
  AssetHealth schema;
* compliance trend, healed-not-double-counted, polygon growth from metric text,
  error clustering, empty-window explanation;
* LFS pointer parse/refusal, ztag parsing, a faked `p4` driving `describe`,
  `print` and suffix-filtered `materialise`;
* URL fetching with size cap and 404 handling, changelist validation, runner hub
  claim/report/401 over real sockets;
* **the server running on both backends**: the same telemetry seeded into
  SQLite and through the PostgreSQL adapter, then `analytics_report`,
  `/api/analytics`, `/api/summary`, `/dashboard` and `/analytics` compared field
  by field - identical. The PostgreSQL side uses a psycopg3-shaped driver double
  that executes the *translated* SQL, fails loudly on any untranslated `?`,
  surviving `INSERT OR REPLACE`, or inline `REFERENCES`, and records the DDL the
  server sends so the two-pass foreign-key strategy is asserted;
* the pre-flight core: budget errors, warnings, sorting, text rendering, fuzzy
  tag suggestion in strict and suggest modes;
* migrations: discovery, gaps, checksums, blocking-DDL refusal, dry run,
  apply/verify/rollback on SQLite, drift detection, and the PostgreSQL
  rewrites (CONCURRENTLY, NOT VALID, identity columns);
* audit: JSON shape, recursive redaction, severity floor, syslog framing and
  priority, webhook batching, failing collectors, bounded-queue drops;
* replicas and failover: a dead replica trips its breaker and queries fall
  back to the primary, the health loop closes the breaker again, and 120
  concurrent queries across 8 threads run clean over the pool;
* the **Blender panel inside Blender 4.0.2 headless** - it imports, registers its
  N-panel and reports a real scene (`CLEAN - nothing to fix`, 12 tris, 1
  material) from the evaluated depsgraph, not from a fixture.

**Needs your infrastructure to verify** (the code paths exist and fail closed,
but nothing here can exercise them end to end):

* a real PostgreSQL server - the driver double proves the SQL we send and the
  shape of the rows we read, not PostgreSQL's own semantics (`agk-enterprise
  doctor` reports the connection);
* a real IdP (Okta / Entra ID / ADFS) for the full redirect round-trip;
* Perforce, Maya 2027, 3ds Max 2027 and Unreal 5.3 have since been driven live
  (see RELEASE_NOTES v1.1.0); the trigger needs `--port`/`--p4user`/`--tickets`
  on a real server (docs/10).

That boundary is stated here rather than implied, because "we integrated with
Active Directory" means something very different in each case.
